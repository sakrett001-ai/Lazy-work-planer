# Рабочий прототип: сначала проверяем пользу

Цель — пройти полный цикл поручения небольшой командой: поставить задачу → получить ответ → увидеть проблему и основания → подготовить решение → принять результат. После пяти рабочих дней использования решаем, что действительно нужно масштабировать.

Здесь описано персональное рабочее пространство с общей SQLite-базой. Старый опубликованный Sites остаётся отдельной демонстрацией; этот сервер там не развёрнут.

## Запуск за несколько минут

Нужен **Node.js 24**. До слияния [PR №3](https://github.com/sakrett001-ai/Lazy-work-planer/pull/3) используй ветку `codex/pilot-workspace`. Для нового каталога:

```sh
git clone --branch codex/pilot-workspace https://github.com/sakrett001-ai/Lazy-work-planer.git
cd Lazy-work-planer
```

Из корня этой копии:

```sh
npm ci
npm run prototype
```

Открой **http://127.0.0.1:8787/assistant/workspace**. В терминале появится одноразовый код руководителя на 30 минут. После входа открой «Участники»: там можно добавить сотрудника и выпустить его приглашение. Для проверки двух ролей используй другой браузер или приватное окно. Сеанс действует 8 часов.

На первом запуске создаются руководитель, два вымышленных сотрудника и шесть примеров задач с датами относительно сегодняшнего дня. Примеры явно отмечены. Для начала без примеров выбери **при первом запуске**:

```sh
npm run prototype -- --empty
```

Повторный запуск сохраняет существующую базу, включая задачи, обсуждения, документы и действующие сеансы. Флаг `--empty` не удаляет данные. Для отдельного чистого пилота можно выбрать новый каталог через `ASSISTANT_DATA_DIR`; используй этот же каталог во всех командах приглашений и резервного копирования. Нажатие Ctrl+C останавливает процесс.

## Что уже можно делать

| Возможность | Как работает |
| --- | --- |
| Постановка и правка поручений | Исполнитель, проект, описание, необязательные срок и реквизиты протокола. Руководитель может поставить задачу себе |
| Живая доска | Цвет по ситуации, срок и обратный отсчёт, персональные закрепления, отметка «Замечено», поиск и фильтры |
| Календарь и Гант | Представления той же базы. Этапы имеют даты и зависимости; завершить этап раньше предшественника нельзя |
| Мурмурация | Включаемое переключение представлений с паузой при взаимодействии. Учитывается системный режим уменьшенного движения |
| Обсуждение | Руководитель пишет и запрашивает статус; исполнитель отвечает по своей задаче. Сообщение сохраняется как источник |
| Сводка и память | Препятствия, запросы переноса, готовность к приёмке, факты с основаниями и история. Неясный ответ вызывает уточнение |
| Документы | Подготовка, редактирование, согласование текста и скачивание `.txt`. Согласование документа не отправляет письмо и не меняет срок |
| Приёмка | Руководитель принимает результат, задача попадает в архив; её можно вернуть в работу |
| Автоопрос внутри приложения | Включается руководителем в «Участниках». Учитывает рабочее время, свежие ответы и уже заданные вопросы |
| ИИ-консультация | Подготовлен отдельный маршрут через eve: чтение памяти, варианты действий, черновики и проверяемые цитаты. Требует настройки модели |

Руководитель видит все поручения этой небольшой команды. Сотрудник — свои задачи и обсуждения; управленческие черновики ему не раскрываются. Разделение на отделы, корпоративный вход, MAX, вложения и достижения остаются следующими этапами.

## Первый сценарий проверки

1. **Руководитель:** создай поручение без протокола; выбери сотрудника, добавь срок и два зависимых этапа. Закрепи карточку, посмотри календарь и Гант.
2. **Руководитель:** открой обсуждение, запроси статус. При желании включи автоопрос в «Участниках».
3. **Сотрудник:** войди по приглашению. Напиши: «Есть препятствие: не получены исходные данные. Нужна помощь руководителя». На доске руководителя появится проблема, в памяти — исходная цитата.
4. **Руководитель:** подготовь запрос данных, отредактируй текст и согласуй его. Скачай документ. В обычном запуске это **редактируемый шаблон**, а не ответ LLM.
5. **Сотрудник:** сообщи об устранении препятствия, заверши этапы, затем напиши: «Работа выполнена, результат готов к проверке». Это запрос приёмки, а не автоматическое закрытие.
6. **Руководитель:** проверь результат и прими задачу. Найди её в архиве; при необходимости верни в работу. Для переноса срока сотрудник отдельно пишет конкретную дату, руководитель отдельно согласует изменение.
7. Перезапусти процесс и проверь память. В двух сеансах проверь новое сообщение при открытой карточке: интерфейс предлагает обновить её, сохраняя введённый текст. Решение по устаревшей версии отклоняется.

Обычный запуск работает без ключей. Консервативные правила разбора и шаблоны явно обозначены; качество понимания свободной переписки ещё предстоит оценить на живой модели.

### Когда ассистент спрашивает сам

В новой базе автоопрос выключен. После включения сервер раз в минуту проверяет задачи: по умолчанию понедельник–пятница, 09:00–18:00 по Москве, не чаще раза в 6 часов после предыдущего запроса или свежего ответа. Исключения календаря и интервал задаются в `settings` исходной конфигурации; производственный календарь автоматически не загружается.

Запрос появляется в обсуждении. Система различает доступное сообщение и подтверждённое прочтение: присутствие пользователя и push-уведомления пока не реализованы. Без ответа по умолчанию через 4 часа ожидания появляется отдельная отметка; выполненность задачи не меняется. Процесс должен оставаться запущенным. При включённой внешней доставке в eve автоматические запросы отдаёт Telegram-расписание, чтобы два канала не опрашивали параллельно.

## Подключение живого ИИ

Рабочий интерфейс и eve используют одни HTTP-обработчики и базу. В режиме eve руководитель задаёт вопрос из карточки; запрос имеет устойчивый ID и серверно проверенного автора. Агент читает память, готовит варианты и документы, завершает ответ через `publish_web_answer`. Веб-консультация не может записывать отчёт от имени сотрудника или отправлять сообщения. Цитаты проверяются по сохранённым источникам; ответ по изменившейся карточке помечается устаревшим.

Сохранена модель из `agent/agent.ts`. Для выбранного строкового ID модели используется Vercel AI Gateway: на самостоятельном сервере нужен `AI_GATEWAY_API_KEY`, в подходящем окружении возможна OIDC-аутентификация. Прямой ключ OpenAI для этого пути не требуется.

Порядок включения на выбранном сервере:

1. Инициализировать базу обычным прототипом или импортом, затем остановить отдельный процесс прототипа.
2. Настроить окружение из `.env.example`: постоянный `ASSISTANT_DATA_DIR`, точный `ASSISTANT_SERVER_ORIGIN`, доступ к Gateway и `ASSISTANT_AI_ENABLED=true`. Секреты хранятся вне Git. Команды npm сами `.env` не читают; переменные должны быть переданы процессу.
3. Выполнить `npm run build`, затем `npm start -- --host 127.0.0.1 --port 8787`. Не запускать два сервера на одном порту. Для эксплуатации сохранить также `.eve/.workflow-data` и настроить HTTPS-прокси для `/assistant/`, `/eve/` и `/.well-known/workflow/` с проверкой доступа к служебным маршрутам.
4. Выпустить приглашение командой `npm run pilot:invite -- manager`, открыть `/assistant/workspace` на настроенном адресе и задать вопрос по одной тестовой задаче. Проверить источник ответа, черновик и поведение при недоступности модели.

В текущей среде этот путь **не прошёл живой запуск**: ранее сборка eve была отклонена автоматической проверкой из-за сетевого обращения к `ai-gateway.vercel.sh`. Повторного обхода ограничения не делали. `ASSISTANT_AI_ENABLED=true` включает функцию, но само по себе не доказывает доступность модели. `eve dev` не запускает производственные расписания; для них нужен проверенный путь build/start.

Telegram-адаптер уже есть в проекте, его реальная доставка требует бота, подтверждённых Telegram ID, HTTPS-webhook и отдельной проверки. Не включай внешние отправки для участников до проверки на своей тестовой учётной записи. Инструкция — [README](../README.md#подключение-реального-пилота). Общение внутри приложения доступно сразу.

## Docker и размещение

Подготовлены `Dockerfile.prototype` и `compose.prototype.yaml` для режима без внешней модели:

```sh
docker compose -f compose.prototype.yaml up --build
```

Адрес в этом варианте — **http://localhost:8787/assistant/workspace**, код входа печатается в журнале процесса. SQLite хранится в именованном томе `assistant-data`, приложение работает от непривилегированного пользователя. Не удаляй том с рабочей базой. Здесь конфигурация подготовлена, но образ **не собирался**: Docker в среде проверки отсутствует.

Для доступа сотрудников с телефонов нужен работающий сервер с HTTPS и постоянным диском; `localhost` другого устройства не откроет твой компьютер. Публичное размещение пока не выполнено. Серверное хранилище и резервная копия обязательны перед реальной работой; схема гибридного облака для первого пилота не нужна.

Резервная копия работающей базы:

```sh
npm run memory:backup -- /path/to/backups/assistant.sqlite
```

Используй новый путь для каждой копии; существующий файл не перезаписывается. Копию держи отдельно от основного диска. При восстановлении останови процесс и используй отдельный каталог данных. Подробности персонального входа и настройки — [PILOT.md](PILOT.md).

## Приёмка перед масштабированием

Один руководитель, 2–3 сотрудника, около 10 несекретных задач, пять рабочих дней. Успех означает, что участники сами проходят весь цикл, сводка помогает заметить проблемы, исходные сообщения не теряются, повтор запроса не создаёт дубль, права и утверждённые сроки соблюдаются, данные восстанавливаются из копии. Для ИИ дополнительно оцениваем реальные русские ответы: обоснованность предложений, необходимость исправлений, задержку и стоимость.

Автоматические проверки: `npm test` и `npm run typecheck`. Они охватывают SQLite, HTTP, права, версии, повторы, рабочее время и действия интерфейса через DOM. Полноценная визуальная проверка браузером, Docker, реальная модель и Telegram остаются отдельными проверками перед использованием соответствующего режима.

Находки из [FINDINGS.md](FINDINGS.md) сохраняются как очередь экспериментов. Масштабирование подразделений и сложной инфраструктуры — после успешного пилота и выявленных ограничений, а не условие первого запуска.
