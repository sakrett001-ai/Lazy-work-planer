# Поручение → дочерние задачи → отчёт

Локальный web/API-срез поверх существующих авторизации, SQLite и версий карточек.
Не запускает модель, внешние сообщения или развёртывание.

## Проверяемый сценарий

1. Руководитель создаёт поручение с ответственным и сроком.
2. В деталях поручения выбирает «Создать дочернее»: задаёт другого исполнителя и отдельный срок. Родитель не перепривязывается, его ответственный и срок сохраняются.
3. Руководитель запрашивает статус. Повторный ручной или автоматический запрос во время ожидания не добавляет сообщение и не обнуляет дату ожидания. Истечение времени ожидания сохраняет «нет ответа», а не начинает новый цикл опроса; фактический ответ разрешает следующий опрос по расписанию.
4. Исполнитель входит в собственной сессии и отвечает по своей карточке: прогресс, препятствие или результат на проверку. Руководитель обновляет доску и видит ответ/историю. Приёмка остаётся действием руководителя.
5. В разделе «Отчёты» руководитель выбирает поручения. По умолчанию выбор родителя отмечает доступные дочерние; любую отметку можно снять. Создаётся датированный текстовый снимок, доступный в истории и для скачивания.

Запуск и вход — по существующему `docs/PILOT.md`/README и скриптам `pilot:serve`, `pilot:invite`; используйте только отдельную тестовую базу и вымышленные записи. Тесты сами создают временную SQLite-базу и независимые сессии:

```sh
npm run typecheck
node --test tests/delegation-reports.test.mjs tests/delegation-ui.test.mjs
npm test
```

## Границы данных и прав

- Дочерняя задача — отдельное поручение, не последовательный этап. Завершение дочерней не завершает родительскую и не переносит срок. Процент исполнения автоматически не выводится.
- `parentId` задаётся только при создании с `expectedParentVersion`. Нельзя создавать под завершённым родителем, перепривязывать существующую задачу, образовать цикл или неограниченную глубину (20).
- Связь не наследует разрешения. Сотрудник видит только собственные задачи, источники и историю; ID недоступного родителя скрыт. Все руководители имеют существующее право чтения задач, но снимок отчёта доступен только создавшему его руководителю. Новые ACL не вводятся.
- Для новых карточек сохраняются `originalDue`/`originalDueTime`. Последующие правки не стирают исходный срок. Для старых записей исходный срок **неизвестен**, текущий не выдаётся за исторический.
- Отчёт принимает не более 50 явно выбранных ID с версиями карточек. Повтор того же requestId возвращает тот же снимок; другой payload с тем же ID отклоняется. Включение дочерних — видимое действие выбора UI, не скрытое серверное расширение прав/состава. Охват потомков и пропуски явно записаны для каждой карточки.
- Все факты, текущий/исходный сроки, версия, дата формирования, источник/его версия/время события и получения копируются в одной транзакции. Политика `current_facts_at_creation`: источник берётся актуальный **при создании**, это не обещание точного совпадения с прежним предпросмотром. Версия карточки проверяется; источники не блокируются версией карточки.
- Сохранённый payload не пересчитывается после правок карточек/источников. Источник в тексте — явно процитированная JSON-строка, не инструкция и не основание всех управленческих полей. `factOrigins` и отдельные evidence сохранены в payload.
- Родительские child summaries пока только в интерфейсе руководителя; существующий модельный контекст и retrieval не расширены. Этот срез не создаёт сотрудников-агентов и не меняет их полномочия.

## Ограничения проверки

Детерминированные API/DOM-тесты не заменяют визуальную проверку браузером и одновременную работу реальных пользователей. Браузерная проверка в текущей среде не выполнена. Нет публично размещённого приложения, live LLM или внешней доставки. Бюджетирование моделей, retrieval-contract и последующие agent-execution сценарии остаются отдельными задачами.
