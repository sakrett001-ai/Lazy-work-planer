# Локальный пилот планера: поручение → канбан → статус → сводка

Проверяем рабочий интерфейс и SQLite, **не статическое демо**. Связь с Маркусом,
Telegram/MAX, модели и публикация не включены. Существующие персональный вход,
проверки прав, версии карточек и правила принятия результата сохранены.

## Запуск

Node.js 24, из корня репозитория:

```sh
npm ci
npm run prototype
```

Открыть `http://127.0.0.1:8787/assistant/workspace`. Ввести одноразовый код
руководителя, который напечатал этот процесс. Не пересылать коды в общий чат.
Команда создаёт примеры **только в пустой базе**; повторный запуск сохраняет задачи.
Для своей новой пустой базы используйте `npm run prototype -- --empty`.
Данные по умолчанию в `.data/assistant.sqlite`; не удалять каталог для перезапуска.
При использовании `ASSISTANT_DATA_DIR` указывать тот же путь во всех командах.

## Один показ без переключения пользователей

1. Нажать **«+ Поручение»**. Название: «Подготовить материалы пилота».
   Исполнитель: руководитель (себе), проект: «Показ программы»; указать будущую
   дату и время, например 16:30 мск. При необходимости раскрыть реквизиты
   протокола: номер, пункт и дата. Нажать **«Поставить задачу»**.
2. Закрыть карточку. Поручение находится в **«Запланировано»**. На самой карточке
   видны исполнитель, проект, реквизиты, точная дата и время, а не только отсчёт.
3. Открыть поручение → **«Начать работу»**. Карточка перемещается в **«В работе»**.
4. В карточке сообщить: «Есть препятствие: данные не получены. Нужна помощь
   руководителя». Карточка переходит в **«Препятствие»**, исходный текст остаётся
   в обсуждении. Раскрыть **«Короткая сводка»**: препятствие и вопрос для решения
   видны по этой же задаче. Это детерминированный разбор, не ответ модели.
5. Сообщить: «Препятствие устранено, данные получены». Затем: «Работа выполнена,
   результат готов к проверке». Карточка переходит в **«На проверке»**, не закрывается.
6. Только руководитель нажимает **«Принять результат»**. Задача появляется в
   фильтре **«Принято»**. При необходимости из карточки можно вернуть её в работу.
7. Остановить процесс (Ctrl+C), запустить ту же команду с тем же каталогом базы.
   Задача, срок, обсуждение и история сохраняются. При истёкшем сеансе войти заново.

Для сценария с сотрудником создать участника, выдать персональное приглашение и
войти в отдельном профиле браузера. Сотрудник видит только назначенные ему задачи;
руководитель не должен выдавать свой код сотруднику.

## Поведение доски

- Четыре колонки открытых поручений и отдельный фильтр принятых результатов.
- Числа в колонках учитывают поиск и текущий фильтр. Общая сводка и верхние
  показатели относятся ко всем доступным пользователю задачам, не только поиску.
- Закреплённые поручения идут первыми **в своей колонке**, без дубликатов.
- На узком экране колонки прокручиваются горизонтально. Доску можно сфокусировать
  клавиатурой; действия остаются обычными кнопками карточки.
- Перетаскивания между состояниями нет: оно не должно обходить сообщение-основание,
  актуальную версию карточки или решение руководителя.
- Поиск без совпадений и пустые колонки показывают отдельные пустые состояния.
- Календарь и Гант остаются представлениями тех же серверных данных.

## Проверки и границы

`npm test`, `npm run typecheck`, `git diff --check`.
Новые проверки покрывают размещение по колонкам, счётчики, точный срок,
закрепление, экранирование, API-цикл с правами/версиями и сохранение SQLite после
открытия новым Node-процессом. DOM-сценарий также проходит создание с потерей ответа
и безопасным повтором, смену состояния, приёмку и архив.

В этой облачной среде полноценная визуальная проверка **не выполнена**:
локальный Chromium не запускается из-за системных ограничений; отдельный облачный
браузер не имеет маршрута к loopback-серверу. DOM-тесты не заменяют проверку реального
desktop/mobile layout. Перед показом открыть рабочий интерфейс на целевой машине,
проверить ширину колонок, форму, прокрутку и пройти указанный сценарий.
Публикация, доступ с других устройств и живой бот — отдельные, не заявленные результаты.
