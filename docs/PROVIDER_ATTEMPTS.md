# Журнал попыток провайдера

Метаданные попыток сохраняются в той же SQLite-базе, таблица `provider_attempts`.
Это журнал наблюдений, **не биллинг**, не финансовый лимит и не подтверждение
стоимости. Новых провайдеров, ключей, сетевых вызовов или автоматических повторов
этот слой не добавляет.

## Граница сохранения

Перед `complete(...)` runner в транзакции проверяет актуальные права/контекст,
маршрут сохранённой консультации и уникальность `(jobId, roleId, call)`, затем
сохраняет `started`. Не удалось сохранить — провайдер не вызывается. Повтор той
же попытки отклоняется, в том числе после перезапуска.

После возврата адаптера `response_received` и доступные счётчики токенов
сохраняются **до** проверки свежести задачи и валидации ответа. Поэтому
изменение контекста/прав, истечение job или неверный ответ не уничтожают
наблюдённую usage. Если сохранить receipt не удалось, ответ не публикуется;
терминальный отказ job переводит оставшиеся `started` в `unknown` атомарно.
При полной недоступности базы подтверждение результата невозможно: сохранённое
`started` остаётся свидетельством неопределённого исхода до восстановления.

| Состояние | Значение |
|---|---|
| `started` | Попытка зарегистрирована; фактическая отправка/результат ещё не подтверждены |
| `response_received` | Адаптер вернул ответ; это НЕ принятие ответа и НЕ подтверждённая стоимость |
| `unknown` | Исход неопределён: ошибка/прерывание/истечение; нельзя считать бесплатным или автоматически повторять |

Сбой между записью `started` и реальным вызовом тоже неопределён: мы не можем
доказать отправку по одной записи. При expiry/отказе job незавершённые попытки
переходят в `unknown`. Поздний ответ с точным внутренним token может дополнить
`observedAt` и usage, но **unknown остаётся unknown**. Ответ задачи и разрешение
нового вызова от этого не меняются. Первое наблюдение ответа неизменно;
повторное завершение не подменяет счётчики. Отсутствующая запись или неверный
token не создают попытку.

## Минимальные данные и доступ

Сохраняются ссылка на job, роль, номер шага, фиксированный provider enum,
временные отметки, состояние, безопасный код ошибки и необязательные
неотрицательные целые `inputTokens/outputTokens`. Нулевой счётчик допустим;
NaN, отрицательные, дробные и слишком большие значения отбрасываются.
Не сохраняются prompt, исходный ответ, сырая ошибка, ключи, имя человека,
название подключения или модели. Ссылка на job — служебная связь, не обещание
анонимности всей базы. Внутренний случайный token хранится отдельно и в API
не выдаётся. Журнал возвращается только как `jobs[].attempts` существующего
авторизованного API истории собственных консультаций руководителя; нового
публичного endpoint нет.

## Проверка и ограничения

`node --test tests/provider-attempts.test.mjs` использует offline adapters,
временную SQLite-базу, управляемые сбои и новые Node-процессы. Живой провайдер
не проверялся. Детализация относится к одному вызову адаптера, не ко всем
внутренним HTTP-запросам (например OAuth). Отсутствующий usage неизвестен, а
не нулевой. Денежная оценка, сверка с провайдером и общий бюджет не реализованы.
Контракт обнаружения источников в большой памяти остаётся отдельным этапом.
