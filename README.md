# Lazy Work Planer · личный ассистент руководителя

Версия 0.3 — интерактивный прототип и основа серверного агента.

Задача: помогать руководителю доводить поручения до результата — собирать статусы, уточнять препятствия, предлагать следующие действия и готовить редактируемые решения.

[Открыть демо](https://rut-personal-assistant.fancytitan16.chatgpt.site) · [План доработок](docs/ROADMAP.md)

Опубликованное демо доступно владельцу проекта через ChatGPT. Для независимого просмотра можно запустить интерфейс локально по инструкции ниже. Интерфейс работает на вымышленных данных; живые модель, Telegram и MAX к нему пока не подключены.

## Быстрый запуск интерфейса

Нужны Git и Python 3. Для просмотра дашборда установка Node.js, зависимостей и API-ключей не требуется.

```sh
git clone https://github.com/sakrett001-ai/Lazy-work-planer.git
cd Lazy-work-planer
python3 -m http.server 8080 --bind 127.0.0.1 --directory dist
```

Открой http://localhost:8080. В Windows вместо `python3` можно использовать `py -3`. Остановить сервер — `Ctrl+C`.

Состояние демо сохраняется в `localStorage` этого браузера. Перенос исходников в GitHub не переносит созданные в браузере поручения и черновики. Ключи и токены в интерфейсе не нужны.

## Работа с исходниками

Для серверной части и проверок нужен Node.js 24; версия указана в `.nvmrc`.

```sh
npm ci
npm test
npm run typecheck
```

`npm run dev` запускает серверный модуль eve, а не статический дашборд. Подключение бота, модели и рабочей базы описано отдельно ниже.

## Что готово

- `dist/` — самостоятельная интерактивная демонстрация дашборда. Содержит вымышленные данные, поиск, память задач и симулятор диалога со сценариями обратной связи. Состояние сохраняется в браузере. Закрытая публикация Sites обслуживает только эту часть.
- `dist/langgraph-emb.js` — локальный граф обработки `TaskMonitor_v2` и поиск по хешированным текстовым признакам (64 измерения). Имя файла сохранено для совместимости; официальный LangGraph и нейросетевая модель эмбеддингов не подключены. `dist/task-memory.js` строит отдельный граф памяти по сохранённым источникам, событиям и решениям.
- `agent/skills/` и `agent/tools/` — скиллы (`langgraph-monitoring`, `semantic-embeddings`) и инструменты серверного агента (`semantic_search`, `run_monitoring_graph`, `notify_employee`) для поиска, разбора проверенных входящих сообщений и адресных отправок после настройки серверного канала. `get_task_memory` восстанавливает контекст задачи из базы.
- `agent/` — серверный модуль на eve: проверенный Telegram webhook, ограниченный доступ к задачам, запись статусов с цитатой, уведомления сотрудникам о новых задачах и запросах статуса, эскалация блокеров руководителю, расписание опросов и сводки.
- `dist/domain.js` — общие правила для интерфейса и серверных инструментов. Дедупликация, история, отдельный учёт отсутствия ответа, запрос переноса без изменения срока, проверка результата до приёмки.
- SQLite хранит задачи, источники и журнал доставки на постоянном диске сервера. Изначально база пуста. Демонстрационные сотрудники автоматически в неё не загружаются.
- MAX предусмотрен как следующий канал; его адаптер пока не реализован.

## Как посмотреть

Открой опубликованный закрытый дашборд. Основной экран — доска карточек, упорядоченных по срочности. Выбери карточку, открой предложение ассистента и подготовь черновик. Добавь своё поручение без протокола и срока. Переключись в календарь или «Этапы и Гант». В разделе «Ассистент» доступен сценарный чат и сохранённые черновики; кнопка проверки сценария показывает четыре сообщения и обновляет карточку. Готовый результат сначала попадает на проверку, после принятия — в архив.

## Подключение реального пилота

1. Создать Telegram-бота через BotFather. Сотрудники сначала сами запускают бота. Их числовые Telegram ID связываются с утверждённым списком участников; произвольные входящие аккаунты не принимаются.
2. Подготовить постоянный Node.js 24 сервер с HTTPS и диском для SQLite и Workflow. Сохранять `ASSISTANT_DATA_DIR` и `.eve/.workflow-data`; проксировать `/assistant/`, `/eve/` и `/.well-known/workflow/`. Модуль не следует размещать с этой SQLite-базой в среде с непостоянной файловой системой. При выборе такого хостинга сначала заменить хранилище на постоянную SQL-базу.
3. Задать секреты из `.env.example` в защищённых настройках сервера. Никогда не вводить токен бота в демонстрационную страницу и не коммитить реальные ключи. `ASSISTANT_DELIVERY_ENABLED=false` оставляет ответы черновиками и отключает плановые отправки.
4. На основе `config/pilot.example.json` подготовить участников и поручения, добавить `telegramId` проверенным участникам, скорректировать даты и календарные исключения. Выполнить `npm run pilot:import -- /path/to/pilot.json`. Импорт работает только с пустой базой, не перезаписывает рабочие записи.
5. Выполнить `npm run build`, запустить сервер через `npm start`, проверить постоянство данных при перезапуске. Задать HTTPS-адрес в `ASSISTANT_SERVER_ORIGIN`; зарегистрировать webhook через `npm run telegram:register`. Этот скрипт изменяет настройку бота; автоматически он не запускался.
6. Проверить на одной тестовой задаче реальное обращение к модели, входящий ответ, уточнение, запись источника и сводку. Затем включить отправки для небольшой группы. Уточняющий ответ должен содержать ID задачи, если иначе задача не определена однозначно.
7. Подключить рабочий интерфейс к защищённому серверу и добавить серверные действия руководителя. Демонстрационный интерфейс пока не связан с живой базой. `/assistant/state` подготовлен для чтения с административной авторизацией; секрет нельзя размещать в статическом JavaScript.

Предлагаемый стартовый ритм: опросы в 10:00 и 16:00 по Москве, сводка руководителю в 17:30 по рабочим дням. Это параметры будущего приложения; задача-автоматизация в ChatGPT не создавалась. Свежий ответ исключает повторный опрос в пределах заданного интервала. Производственный календарь подключается отдельно через исключения; код не считает все будни рабочими автоматически для любых лет.

## Проверка

`npm test` проверяет существенные правила: права на задачу, повторную доставку, неверную цитату, позднее сообщение, сроки, состояния, молчание, рабочее время и календарные границы. `npm run typecheck` проверяет серверные типы. `npm run build` собирает агент.

Проверки включают отрицания, неизвестные и неоднозначные даты, права на результаты поиска, привязку к сохранённому источнику, повторы, поздние сообщения, состояние отправки и память после запуска нового процесса. Серверные тесты используют настоящий SQLite и определения инструментов eve; Telegram заменяется локальным имитатором транспорта. Тест резервного копирования проверяет сохранность state, inbox и outbox из работающей WAL-базы.

jsdom проверяет DOM и действия, включая карточку памяти и ссылки на источники; он не проверяет отрисовку. Полноценная браузерная проверка недоступна в текущей среде. Сборка eve ранее была остановлена автоматической проверкой безопасности из-за обращения сборщика к `ai-gateway.vercel.sh`; повторно не запускалась и не считается проверенной. Живые модельные ответы и Telegram не проверены, MAX не подключён. Sites обслуживает только `dist/`.

## Память задач и надёжность обработки

- **Сохраняемая память:** карточка, исходные сообщения, история изменений, решения руководителя и черновики хранятся в SQLite. У каждого изменённого факта сохраняется основание `factOrigins`; неясный ответ не становится основанием старой сводки. Старые записи без основания остаются явно помеченными как данные карточки.
- **Граф памяти:** узлы задачи, исполнителя, проекта, протокола, этапов, источников, событий и черновиков связаны явными отношениями. Он восстанавливается из сохранённых записей. Сходство текстов не создаёт доказанных связей. Технический журнал последних запусков можно сократить без удаления памяти.
- **Восстановление контекста:** `get_task_memory` возвращает актуальные факты, основания, решения, открытые вопросы и страницы истории. Telegram-канал добавляет короткий контекст задачи к каждому проверенному сообщению; после смены сессии агент может получить полную историю инструментом. `get_decision_context` также включает эту память.
- **Доступ:** поиск, похожие задачи и память ограничены серверной ролью. Сотрудник видит свои задачи; управленческие черновики доступны руководителю. Интерфейсные области остаются фильтрами демо.
- **Источники:** серверный `run_monitoring_graph` требует сохранённый SOURCE_ID. Модель не задаёт автора, время или привязку произвольным текстом. Повтор источника не дублирует события; позднее сообщение сохраняется без отмены более свежего статуса или решения.
- **Разбор:** модель может передать структурированный report с цитатой. Без него применяется консервативный демонстрационный обработчик `feedback.js`. Неоднозначная задача и отсутствующая дата требуют уточнения. Проверяются явные отрицания и обоснованность даты; сложный естественный язык всё равно требует отдельной оценки качества. Проценты «точности» не показываются.
- **Доставка:** граф и кнопки статического интерфейса только подготавливают уведомления. Серверный `notify_employee` фиксирует фактический результат транспорта. Отсчёт ответа начинается только после sent; устойчивый ID вызова защищает от повторной отправки. `uncertain` требует разбирательства, автоматический повтор не выполняется.
- **Интерфейс:** в карточке доступна «Память и связи задачи» с фактами, сообщениями, решениями и историей. Трасса обработки свёрнута. Неоновая доска, закрепления, пульсация, календарь, Гант и мурмурация сохранены.

Демо хранит данные в браузере, сервер — на постоянном диске. Граф сам по себе не гарантирует сохранность диска или правильность вывода модели. Подключение интерфейса к серверу, авторизация пользователей и живой пилот остаются отдельным этапом.

### Резервная копия памяти

На сервере с настроенным ASSISTANT_DATA_DIR:

```sh
npm run memory:backup
# Или укажи новый файл для копии:
node scripts/backup-state.mjs /secure/backups/assistant-2026-10-15.sqlite
```

Команда создаёт согласованную копию SQLite вместе с входящими и исходящими сообщениями и проверяет её целостность. Существующий файл не перезаписывается. Копию нужно отдельно сохранять на другом диске или в защищённом хранилище; расписание и внешнее хранение здесь не настраиваются. Для восстановления остановить сервер, сохранить прежний каталог данных отдельно, затем поместить проверенную копию как assistant.sqlite в новый каталог ASSISTANT_DATA_DIR без старых WAL/SHM-файлов. Не включать базу и резервные копии в Git.

## Новое в версии 0.3

- Закрепление открытых задач в отдельной верхней группе. Порядок закреплений сохраняется в браузере, поиск и область задач продолжают действовать. При приёмке закрепление снимается.
- Мягкая пульсация контура важных карточек: препятствия, переносы, истёкшие и близкие сроки, проверка результата, отсутствие ответа. «Замечено» гасит конкретный сигнал без изменения задачи. Новое значимое изменение снова привлекает внимание.
- Пульсация отключается отдельно; системное уменьшение движения оставляет статичную подсветку.
- Режим «Мурмурация»: ручной запуск смены доски, календаря и Ганта каждые 15, 30, 60 или 120 секунд. Состав очереди настраивается. Настройки сохраняются, запуск после перезагрузки всегда ручной.
- Реакция на важные события, на любые обновления или только переключение по таймеру. Событие выбирает подходящий экран, сохраняет выбранную область задач и не меняет сами данные. Между событиями выдерживается интервал; повторные обновления одной задачи объединяются.
- Показ приостанавливается при открытой карточке или форме, вводе, поиске, фильтре, в скрытой вкладке и на экране вне очереди. После действия действует пауза 8 секунд. Таймер возобновляется с полным интервалом; события дожидаются окончания взаимодействия.
- Кнопка с пульсом рядом с «Включить» создаёт явно подписанный пример события, не меняя задачу. Логика реализована в `dist/attention.js`.

Это пока три представления одной доски. Отдельные дашборды подразделений и реальные события от сотрудников потребуют серверного подключения. Автопоказ работает только в открытой вкладке; фоновая автоматизация ChatGPT не создавалась. Хранилище `rut-assistant-demo-v02` сохранено для совместимости с предыдущей версией.

Статический интерфейс пока не связан с этими инструментами.


## Ограничения первой версии

Личные текстовые диалоги; голос, вложения, импорт Excel и массовое создание поручений пока не добавлены. Адаптер Telegram работает по явно указанному ID поручения, иначе агент уточняет его. Модель составляет интерпретацию ответа: наличие цитаты и корректного формата не гарантирует смысловую точность. Качество разбора нужно оценить на реальных примерах перед подключением всей команды.

Смена модели возможна в `agent/agent.ts`. Сохранён стартовый провайдер, выбранный eve; обучение своей модели не требуется. Определить оптимальную небольшую модель и бюджет лучше после тестового набора русскоязычных ответов.
