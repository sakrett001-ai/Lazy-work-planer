# Поиск и память задач

1. Вызови semantic_search с описанием темы. Инструмент ограничивает и основную выдачу, и похожие задачи правами пользователя. Черновики руководителя не раскрываются сотрудникам.
2. Считай score оценкой текстового сходства, не вероятностью правильного ответа. Индекс использует 64-мерные хешированные признаки, основы слов и словари; нейросетевая модель эмбеддингов не подключена.
3. Если подходят несколько задач, покажи доступные ID и уточни нужную. Не связывай исходное сообщение с задачей только по первому результату поиска.
4. Вызови get_task_memory для выбранной задачи. Раздели current, подтверждающие sources, события timeline, recentDecisions, предложения drafts и openQuestions. Для старых событий используй page.nextBefore. История в постоянной базе доступна вне текущей сессии.
5. Подкрепляй факты идентификатором источника и датой. Смена статуса или срока имеет собственное основание в facts.origin. Последнее сообщение может быть неясным или запоздавшим, поэтому оно не обязательно подтверждает текущую сводку.
6. Отсутствие источника обозначай явно. Не достраивай связи и договорённости по сходству, собственной памяти диалога или диагностической трассе графа.
