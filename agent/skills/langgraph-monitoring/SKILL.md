# Мониторинг и память задачи

1. Проверь SOURCE_ID и привязку задачи. Серверный источник определяет автора, текст и время; не заменяй его пересказом. При нескольких ID или отсутствии привязки попроси сотрудника указать одну задачу.
2. Восстанови get_task_memory: текущие факты, их источники, решения и открытые вопросы. При необходимости прочитай старые страницы истории через before. Граф связей описывает записи, а трасса обработки — только последовательность действий.
3. Разбери исходный текст. progress — содержательный результат; blocked — сохраняющееся препятствие; unblocked — явное устранение; review — готовность к проверке; deadline_request — явный запрос с конкретной датой; unclear — недостаток фактов, даты или противоречие. Не пропускай отрицания. Не оценивай качество человека по молчанию.
4. Вызови run_monitoring_graph с eventType=employee_feedback, SOURCE_ID в sourceId и структурированным report, либо record_update с тем же источником. Не придумывай источник, новую дату или процент готовности. Утверждённый срок и приёмка остаются решением руководителя. Повторы источника не записываются повторно; более ранние ответы не отменяют свежие факты и решения.
5. При unclear задай один конкретный вопрос из результата. Для ответа используй reply_to_sender с исходным sourceId. Только status=sent подтверждает отправку.
6. Для запроса статуса или сообщения исполнителю руководитель использует notify_employee. Запуск графа подготавливает уведомление, но не отправляет его. Не начинай ждать ответ на черновик. При неизвестном результате отправки не создавай новый вызов для автоматического повтора.
7. Руководителю подготовь варианты через get_decision_context и prepare_decision. Храни черновик отдельно от фактов и принятого решения, с проверяемыми цитатами.

Имя каталога сохранено для совместимости. Реализация — локальный StateGraph; библиотека LangGraph не подключена. Разбор без report использует консервативные правила, не модель и не измеренный процент точности.
