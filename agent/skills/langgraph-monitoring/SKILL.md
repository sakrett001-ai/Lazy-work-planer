# Навык: LangGraph-оркестрация мониторинга рабочих задач (`langgraph-monitoring`)

Используй этот протокол при обработке входящего фидбека от сотрудников, постановке новых поручений и координации действий между руководителем и исполнителями.

## Узлы графа состояния (`LangGraph_TaskMonitor_v1`)

1. **`ingest_signal` (Приём и аутентификация)**
   - Проверь отправителя (`principalId` и `role`) через серверный контекст.
   - Определи упомянутые ID поручений (`П-101`, `З-301` и т.д.).

2. **`emb_retrieve` (Векторное обогащение контекста)**
   - Вызови `semantic_search` для поиска релевантных поручений, похожих препятствий и прошлых сообщений сотрудников в 64-мерном векторном индексе.
   - Если ID поручения не указан явно, сверь кандидатов из векторного индекса, но при неоднозначности всегда уточни ID у сотрудника.

3. **`classify_intent` (Классификация намерения и извлечение фактов)**
   - `progress` — конкретное продвижение по задаче или этапу.
   - `blocked` — возникла проблема, нехватка данных или зависимость; зафиксируй точную формулировку в `blocker` и `needsDecision`.
   - `unblocked` — явное подтверждение устранения препятствия.
   - `review` — работа выполнена со слов сотрудника и передаётся на проверку руководителю.
   - `deadline_request` — запрос на перенос срока с конкретной предлагаемой датой `proposedDue` (`YYYY-MM-DD`).
   - `unclear` — ответ без фактов («в работе», «занимаюсь», «всё ок»).

4. **`validate_guardrails` (Защитные инварианты)**
   - Сотрудник может обновлять только свои открытые поручения.
   - Дословная цитата (`quote`) обязана присутствовать в исходном тексте сообщения.
   - Утверждённый срок (`due`) никогда не меняется автоматически по запросу сотрудника.
   - Статус `done` устанавливает только руководитель после проверки.

5. **`mutate_task_state` (Детерминированная фиксация)**
   - Вызови `record_update` или `run_monitoring_graph`, чтобы сохранить обновление, источник и событие в истории задачи.

6. **`dispatch_notifications` (Двусторонняя коммуникация и уведомления)**
   - Сотруднику: подтверди фиксацию статуса (`reply_to_sender`) или отправь уведомление о новой задаче / запрос статуса (`notify_employee`).
   - Руководителю: при `blocked`, `deadline_request` или `review` сформируй сигнал с источником и вариантами решения (`get_decision_context` → `prepare_decision`).
